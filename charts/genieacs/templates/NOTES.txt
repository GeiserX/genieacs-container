GenieACS has been deployed successfully!

1. To access the GenieACS UI, follow these instructions:

{{- if or .Values.ingress.enabled .Values.httpRoute.enabled }}
   The GenieACS UI is accessible through the configured route resource(s):

   {{- if .Values.ingress.enabled }}
   Ingress:
   {{- range .Values.ingress.hosts }}
     http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host }}{{ with .paths }}{{ (index . 0).path }}{{ end }}
   {{- end }}
   {{- end }}

   {{- if .Values.httpRoute.enabled }}
   {{- $path := "/" }}
   {{- with .Values.httpRoute.matches }}
   {{- with (index . 0).path }}
   {{- $path = .value | default "/" }}
   {{- end }}
   {{- end }}
   HTTPRoute host/path:
   {{- range .Values.httpRoute.hostnames }}
     {{ . }}{{ $path }}
   {{- else }}
     (any hostname accepted by the Gateway listener){{ $path }}
   {{- end }}
   {{- end }}
{{- else }}
   NOTE: The ingress and HTTPRoute are disabled, and you might need to use port-forwarding to access the UI.

   Run the following command to forward the port:

     kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "genieacs.fullname" . }}-http 8080:{{ .Values.service_http.port_http }}

   Then access the UI at: http://127.0.0.1:8080/
{{- end }}

2. The UI login tokens are signed with GENIEACS_UI_JWT_SECRET, taken from
{{- $jwt := include "genieacs.uiJwtSecret.source" . }}
{{- if eq $jwt "existingSecret" }}
   the Secret "{{ .Values.uiJwtSecret.existingSecret }}", key "{{ .Values.uiJwtSecret.existingSecretKey }}".
   After you rotate it there, restart the pods to pick it up:

     kubectl --namespace {{ .Release.Namespace }} rollout restart deployment/{{ include "genieacs.fullname" . }}
{{- else if eq $jwt "value" }}
   env.GENIEACS_UI_JWT_SECRET in your values, so it is stored in the Deployment spec.
   To keep it out of values files, put it in a Secret and set uiJwtSecret.existingSecret
   instead (values.yaml shows the commands).
{{- else }}
   your extraEnvVars entry named GENIEACS_UI_JWT_SECRET.
{{- end }}

3. Ensure that the MongoDB database is running and accessible. If you enabled the bundled MongoDB chart, it should be running within your cluster.

4. For further configuration and customization, refer to the GenieACS Container documentation and modify the `values.yaml` as needed.
